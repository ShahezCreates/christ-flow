# CHRIST FLOW — Project report structure

## 1. Problem statement
Students at a busy campus repeatedly lose time because they cannot easily see current demand at food, printing, study and activity points before walking to them.

## 2. Proposed solution
CHRIST FLOW is a C-powered decision-support prototype that converts campus activity signals into occupancy, estimated wait, flow score and recommendation outputs.

## 3. Objectives
- Reduce avoidable waiting.
- Help students compare nearby options.
- Demonstrate practical C programming.
- Provide a polished web interface without making the frontend the core academic logic.

## 4. Technology
C, Node.js, HTML, CSS, JavaScript, JSON.

## 5. Limitations
The current prototype uses simulated data. It does not access private university systems or claim real-time campus measurements.

## 6. Future scope
Anonymous crowd reporting, approved sensor feeds, historical demand analysis, accessibility-aware routing, event-aware demand prediction, and a university-approved deployment.
